**AES-256 (Advanced Encryption Standard, 256-bit key)** is a symmetric block cipher with a **128-bit block size** and **14 transformation rounds**. It is the industry standard for encrypting data in transit ([[TLS]]) and at rest ([[SSE]]), with hardware acceleration (AES-NI) on modern CPUs.

## Modes of Operation

The cipher mode is as critical as the key size:

- **AES-256-GCM (Galois/Counter Mode)**: The modern default. It is an **AEAD** (Authenticated Encryption with Associated Data) mode providing both confidentiality and integrity/authenticity (via an authentication tag) in a single pass.
- **AES-256-CBC (Cipher Block Chaining)**: Legacy confidentiality-only mode. Must be paired with an independent MAC (Encrypt-then-MAC) and is prone to padding oracle attacks if error handling leaks padding validity.
- **AES-ECB (Electronic Codebook)**: Unsafe for multi-block data—identical plaintext blocks produce identical ciphertext blocks, leaking structural patterns.

Why is AES-256-GCM preferred over AES-256-CBC?::AES-256-GCM is an AEAD mode providing both confidentiality and integrity/authenticity in one pass, avoiding CBC's padding oracle vulnerabilities and separate MAC pitfalls.

## Envelope Encryption in Production

Rather than encrypting gigabytes of data directly with a master key, cloud systems use **envelope encryption**:

In envelope encryption, data is encrypted with a per-object ==Data Encryption Key (DEK)==, which is itself encrypted by a KMS-managed ==Key Encryption Key (KEK)==.

This allows fast local encryption (the plaintext DEK lives only in memory), simple key rotation (re-wrap DEKs without re-encrypting the underlying data), and centralized KMS auditability.

> [!warning] Failure modes & trade-offs
> - **GCM nonce/IV reuse catastrophe**: Reusing a 96-bit nonce with the same key in AES-GCM destroys confidentiality (attackers recover the XOR of plaintexts) **and** leaks the GHASH authentication key, enabling arbitrary ciphertext forgery. With random 96-bit nonces, rotate the key well before \(2^{32}\) encryptions (birthday bound), or use deterministic counters / AES-GCM-SIV.
> - **AES-256 vs AES-128**: AES-256 runs 14 rounds vs 10 (~40% more compute without AES-NI), offering extra post-quantum margin (Grover's algorithm halves effective symmetric strength to 128 bits). With AES-NI hardware acceleration, the throughput difference is usually negligible.
> - **Key management > algorithm choice**: Hardcoding keys in source code or unencrypted env vars defeats AES-256 entirely; store master keys in a KMS or HSM.

Never use AES-ECB for multi-block data because identical plaintext blocks encrypt to identical ciphertext blocks. #card-reminder

## What happens if you reuse a nonce (IV) with the same key in AES-GCM? #card

Nonce reuse under the same key is catastrophic in AES-GCM:
1. **Confidentiality breaks**: Because GCM uses CTR mode under the hood, XORing two ciphertexts cancels the keystream and reveals `P1 XOR P2`.
2. **Authenticity breaks**: Reusing a nonce allows an attacker to algebraically recover the GHASH authentication key `H` and forge valid authentication tags for arbitrary future messages.

**Mitigation**: Never reuse a `(key, nonce)` pair—rotate keys via KMS/envelope encryption before the birthday bound (~2^32 random 96-bit nonces) or use AES-GCM-SIV for nonce-misuse resistance.
