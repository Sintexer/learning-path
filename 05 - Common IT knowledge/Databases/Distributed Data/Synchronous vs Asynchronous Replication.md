In **Synchronous** [[Replication]] the leader must **block all writes** and wait until the ack of 1..N followers. Usually in [[Relational Database]]s this number is set to 1 (other nodes are asynchronous replica). That is somites called *semi-synchronous*. That guarantees that in case of a leader failure at least 1 follower might become the leader with up-to-date data. It is impractical to make all followers synchronous: any one node outage would cause the whole system to grind to a halt.

Often, [[Leader-Based Replication]] is configured to be completely **asynchronous**. In this case, if the leader fails and is not recoverable, any writes that have not yet been replicated to the followers are lost. This means that a write is not guaranteed to be durable, even if it has been confirmed to the client.
